# Модуль 2. Из идеи в понятную задачу

Цель — договориться о полезном результате до выполнения. Вход: сырая мысль или конкретное поручение.

## Пять опор

1. Зачем и для кого это нужно?
2. Что должно получиться?
3. На какие материалы опираемся?
4. Какие ограничения и действия допустимы?
5. Чем проверим готовность?

Для неопределенной идеи используй [шаблон идеи](../../templates/idea-template.md), для выполнения — [короткий шаблон задачи](../../templates/task-template.md). Необязательно заполнять оба.

## Пример

Было: «Помоги с семейным праздником».

Стало: «Подготовь план двухчасового праздника дома для шести человек. Бюджет 6 000 ₽, покупки не делать. В плане нужны расписание, список подготовки и смета; текущие цены без источника не придумывать».

Критерии: расписание укладывается в два часа; стоимость известных позиций посчитана; неизвестные цены обозначены. Если полная смета неизвестна, утверждать соблюдение бюджета нельзя.

## Диалог

```text
Прочитай мою идею. Коротко перескажи результат и ограничения.
Задай только вопросы, без которых меняется следующий шаг, по одному.
Предложи небольшой первый результат и способ его проверки.
Если остальное ясно, начни безопасную подготовку.
```

Не требуется определенное число вопросов. Не нужно проводить анкету, если цель уже ясна.

## Практика и проверка

Ученик записывает два проверяемых признака готовности. Если важного сведения не хватает, отмечает, какой вывод пока делать нельзя: например, неизвестная доставка не позволяет назвать полный бюджет. Агент готовит короткую карточку задачи. Ученик может по ней объяснить, что войдет в первый результат и что останется на потом.
