# Модуль 7. Собственные скилы

## Цель

Понять, когда база знаний может превратиться в собственный скил, и научиться проектировать простой скил под повторяемые задачи.

## Главная мысль

Скил - это не просто папка со справкой. Это способ научить агента повторяемому подходу: когда использовать знания, какие шаги выполнять, какие ресурсы читать и как проверять результат.

## База знаний и скил

База знаний полезна, когда нужно сохранить информацию по теме.

Скил полезен, когда нужно, чтобы агент снова и снова действовал определенным образом.

Пример:

- база знаний: “что мы знаем о подготовке презентаций для внутренних встреч”;
- скил: “как агент должен помогать готовить презентацию для внутренней встречи: вопросы, структура, критерии, проверка, шаблоны”.

## Когда стоит создавать скил

- Задача повторяется.
- Есть понятный workflow.
- Есть доменные правила.
- Есть шаблоны или примеры.
- Есть типичные ошибки.
- Есть проверка качества.
- Есть ресурсы, которые агент должен использовать.

## Когда лучше не создавать скил

- Задача разовая.
- Процесс еще не стабилизировался.
- Нет примеров реального применения.
- Достаточно обычного `idea.md`, `task.md` и `knowledge-base/`.

## Из чего состоит скил

Минимально:

```text
skill-name/
  SKILL.md
```

Часто дополнительно:

```text
skill-name/
  SKILL.md
  references/
  scripts/
  assets/
```

`SKILL.md` содержит краткие инструкции для агента.

`references/` содержит подробную справку, которую агент читает при необходимости.

`scripts/` содержит команды или программы для повторяемых технических операций.

`assets/` содержит шаблоны, изображения, примеры, заготовки и другие файлы.

## Практика

Возьми одну базу знаний из проекта и ответь:

- эта тема повторится в будущем?
- есть ли устойчивый процесс?
- какие шаги агент должен выполнять?
- какие ошибки он должен избегать?
- какие reference-файлы нужны?
- нужны ли scripts или assets?
- как проверить, что скил помогает?

## Запрос агенту

```text
Проанализируй knowledge-base/ и нашу историю работы по задаче. Определи, есть ли здесь повторяемый процесс, из которого стоит сделать скил.

Если скил нужен:
1. предложи название;
2. опиши, когда он должен срабатывать;
3. предложи структуру SKILL.md;
4. укажи, какие материалы вынести в references/;
5. укажи, нужны ли scripts/ или assets/;
6. предложи способ проверки скила на новой задаче.

Если скил не нужен, объясни почему и что лучше оставить просто в базе знаний.
```

## Результат модуля

Ученик понимает, как из повторяемого опыта и базы знаний рождается собственный скил.
