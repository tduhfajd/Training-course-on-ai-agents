# Модуль 5. Инструменты, скилы, MCP и плагины

## Цель

Понять, как расширять возможности агента инструментами, не превращая процесс в технический хаос.

## Главная мысль

Инструменты нужны не “для красоты”, а под конкретную работу.

## Типы инструментов

- Агентная среда: Codex.
- IDE для просмотра и ручной работы: Cursor, VS Code.
- Репозиторий: GitLab, GitHub, локальный Git.
- Файловое хранилище: NAS, NextCloud.
- Скилы: инструкции для повторяемых типов задач.
- MCP-серверы: доступ к внешним системам и данным.
- Плагины: готовые расширения возможностей.
- Браузер и поиск: исследование и проверка актуальности.

## Markdown как базовый формат

Для учебных и рабочих проектов удобно вести основную документацию в `.md`:

- `idea.md` - сырая идея;
- `task.md` - конкретная задача;
- `knowledge-base/*.md` - база знаний;
- `decisions.md` - важные решения;
- `results/*.md` - итоговые материалы.

Markdown хорошо выглядит в репозитории, легко читается человеком и агентом, хорошо версионируется в Git.

Если нужен другой формат, его можно получить позже:

- PDF для отправки или печати;
- DOCX для редактирования в Word;
- PPTX для презентации;
- HTML для публикации.

Главная мысль: Markdown - источник, остальные форматы - производные артефакты.

## Как объяснять новичку

Не начинать со слов “MCP” и “скилы”. Сначала показать задачу:

- нужно прочитать файлы;
- нужно найти источники;
- нужно создать документ;
- нужно проверить сайт;
- нужно подготовить презентацию.

Потом показать, какой инструмент помогает именно здесь.

## Продвинутый слой: собственные скилы

Если задача или тип задач повторяется, можно создать собственный скил.

База знаний может стать основой скила, если в ней есть:

- устойчивый процесс;
- правила принятия решений;
- частые ошибки;
- шаблоны;
- специфические знания;
- ссылки на полезные ресурсы;
- повторяемые команды или scripts.

Но не любую базу знаний стоит превращать в скил. Если информация нужна один раз, достаточно оставить ее в `knowledge-base/`. Скил нужен тогда, когда хочется, чтобы агент снова и снова применял один и тот же подход.

В Codex для этого может использоваться специальный процесс создания скилов. В этой среде доступен `skill-creator`, который помогает спроектировать структуру скила, `SKILL.md`, references, scripts и assets.

## Практика

Ученик описывает одну свою задачу и отвечает:

- какие файлы нужны;
- нужен ли интернет-поиск;
- нужна ли база знаний;
- нужен ли репозиторий;
- нужен ли специальный инструмент;
- есть ли повторяемый процесс, из которого позже можно сделать скил;
- как проверить результат.

## Результат модуля

Ученик умеет выбирать минимальный набор инструментов под задачу и понимает, когда стоит задуматься о собственном скиле.
